## 3. H1 Verification Suite Summary

1. **Async Event-Loop Responsiveness (`H1.1`):**
   - All synchronous BigQuery queries (`query_data`, `execute_certified_query`, `DocumentDraftingEngine.draft`), Vertex AI Search calls (`PolicySearchEngine.search`), and `SemanticRouter.route` calls are offloaded to worker threads (`asyncio.to_thread`).
   - ADK `FunctionTool` wrappers in `app/agent.py` are native `async def` coroutines.
   - Gemini Live (`app/live_session.py`) dispatches `tool_call` execution as tracked background tasks off `session.receive()`, keeping event-loop tick latency `< 20 ms` (target `< 100 ms`) under 3 concurrent sessions (`tests/test_h1_hardening.py::test_h1_1_event_loop_never_blocks_over_100ms_under_3_concurrent_sessions`).
2. **SQL Safety & Parameterization (`H1.2`):**
   - `SemanticLayer.validate_sql_safety` strips comments (`--`, `/* */`), masks string literals, rejects multi-statement `;`, normalizes backtick-split references, enforces `proj == GCP_PROJECT` and `dataset in ALLOWED_DATASETS`, and blocks unauthorized tables (`hrfin_bronze`, external projects, `INFORMATION_SCHEMA`).
   - Silent self-repair (`QueryDataEngine.repair_sql`) re-applies `apply_query_craft_rules`, `validate_sql_safety`, and `dry_run_check` before execution.
   - `certified_query.py` validates parameter strings against `_UNSAFE_PARAM_RE` and uses `bigquery.ScalarQueryParameter` on the fallback path.
   - All hardcoded `ongc-hr-finance-agent` SQL strings in `turn_runner.py` and `access_control.py` use `{GCP_PROJECT}`, and `FX_INR_PER_USD` (`88.33`) is externalized to `app/config.py` (`D-34`).
3. **Export Security, Proxy & Memory Bounds (`H1.3a`, `H1.3b`, `H1.5a`):**
   - `DocumentExporter.safe_path()` blocks path traversal, forces the writer's extension, uses 128-bit `exp_<32 hex>` IDs, and sweeps expired exports (`14/14` in `tests/test_export_security.py`).
   - `SessionMemory` and `SessionManager` bound `turns <= 50`, `visual_history <= 20`, `spec_history <= 20`, stored table rows `<= 50` (without mutating the caller's contract), strip `all_rows`, and cap active sessions at `<= 200` (with ADK session/event pruning in `turn_runner.py`). Verified flat over a 200-turn soak (`tests/test_h1_hardening.py::test_h1_3b_session_memory_bounds_200_turn_soak`).
   - `ToolResultCache` and `AnswerCache` return deep copies under a lock (`test_h1_3b_cache_immutability`).
   - `validate_and_repair_contract` repairs schema drift (`language='en-IN'` → `'en'`, persona casing, overlong `display_text`) so validation never throws an unhandled HTTP 500.
4. **Note on Held-Out Stress Suite (`50%–75%` vs `80%` target):**
   - Held-out stress prompts are by design out-of-distribution/adversarial prompts (missing domains, unmapped tables, policy edge cases) that fall back (`intent="other"`) to the legacy ADK `gemini-2.5-flash` path. Across `B2`–`H1`, the legacy LLM's wording on whether a data gap is phrasing-classified as a refusal vs a data-gap note fluctuates between `50%` and `75%` (`10/20` to `15/20`), while refusal governance on the stress suite is **20/20 (100%)** and ungrounded numbers are **0/20**.
