### B. Query-Craft Issues Informing Agent Architecture (Lessons for Phase 6 Agent Build)
Debugging the 42 zero-row/error queries revealed crucial schema nuances that the future Agentic SQL Generator must handle dynamically:

1. **Case-Insensitive Categorical Matching (`LOWER(col)`)**:
   - `mart_field_economics` and `mart_production_reserves` store `onshore_offshore` as lowercase (`'onshore'`, `'offshore'`), whereas user queries typically use title case (`'Onshore'`). The agent prompt must mandate `LOWER(onshore_offshore) = 'onshore'` across all asset queries.
   - `mart_workforce` stores `cadre` as `'executive'`, `'non_executive'`, `'board'`. Exact string comparisons with `'Executive'` silently return 0 rows.
2. **Cross-Layer Medallion Routing (Gold vs Silver)**:
   - `mart_production_reserves` in gold only rolled up development drilling for FY26; the granular exploratory well discoveries (oil/gas discoveries vs dry holes) reside in `hrfin_silver.wells_drilled`. The agent router must route well result analyses to `silver.wells_drilled`.
   - `mart_corporate_performance` is a multi-grain mart with many NULL attributes per row. Aggregate metrics (like customer receivables aging) must query `hrfin_silver.receivables` directly for full transaction fidelity.
3. **Normalized Field Names vs Domain Intuition**:
   - In `mart_workforce`, broad functions are generic (`'technical'`, `'support'`, `'finance'`), whereas technical specializations (Geology, Geophysics, Reservoir, Drilling) reside in `discipline_name`.
   - In `mart_hse_incident`, severity tiers use underscores (`'Tier_1'`, `'Tier_2'`), not spaces (`'Tier 1'`).
   - In `mart_travel_claims`, the approved expenditure column is `approved_amount_inr` (not `total_amount_inr`).
4. **Cross-Table Dimension Joins**:
   - `mart_field_economics` contains financial performance, but field geological maturity (`mature`, `growth`, `frontier`) is in `silver.dim_field`. An explicit join on `field_id` is required.
   - `silver.icc_committees` stores `wc_id` without work centre names; a join on `dim_work_centre` is needed for user-facing reports.
5. **Distribution Threshold Realism**:
   - Querying for encashable earned leave balances `>= 250` returned 0 rows because the synthetic distribution strictly caps in-service encashable leave at `238` days. The agent must use dynamic quantiles rather than arbitrary external thresholds.
