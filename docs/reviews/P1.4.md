## 4. Must-fix
**M1. The FY23 standalone C&CE in the cash-flow statement is a filing error, but it is emitted as clean `CF.CCE_CLOSE` / `CF.CCE_OPEN` (`financial_ssot/extract/xbrl.py:227-233`; `docs/reviews/P1.4_evidence.md` §5 item 3).**
- What the XBRL has: opening **0.00**, Δ 27.08, closing **27.08** ₹ cr. The filer left the opening blank and computed closing = 0 + Δ.
- What the AR has (AR FY24:14442-3 FY23 column, AR FY23:11765-6): opening **501.05**, Δ 270.89, closing **771.94** ₹ mn. The same XBRL file's balance-sheet `CashAndCashEquivalents` (OneI) = **77.19** ₹ cr, which agrees with the AR.
- So the evidence's claim that "FY24 S opening 77.19 vs FY23 S closing 27.08" shows the openings are unreliable is backwards. FY24 opening 77.19 is correct, and both FY23 S values are wrong.
- Change: add one deterministic rule. If the C&CE opening fact = 0 **and** closing = `IncreaseDecreaseInCashAndCashEquivalents` for the same context, append `cf_cce_filing_defect` to both facts and set `proposed_line_code=None`, so they cannot backfill gold. Optionally also add a standalone-only flag when closing ≠ the same file's balance-sheet `CashAndCashEquivalents` OneI. Do not make that one a hard rule: consolidated values differ legitimately because of overdrafts, e.g. FY24 C −2,365.68 vs 4,132.75.
- Also: add a test asserting the FY23 S flag, and rewrite evidence §5.3.
