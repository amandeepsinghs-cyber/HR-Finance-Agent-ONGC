## Verdict
**CHANGES REQUESTED**. The escalation is closed: the persona comes only from the signed token, live and in tests. ## 4. Findings
| Severity | File:line | Finding | Required change |
|---|---|---|---|
| **Must-fix 1** (Important) | `yukti/backend/app/auth.py:157-169` | `verify_token` crashes when the signature (or any segment) contains non-ASCII characters. `hmac.compare_digest(str, str)` raises `TypeError`, which falls through to the global handler as HTTP 500 instead of 401. I reproduced this live with a Bearer token ending in `é`. The auth path must never 500 on attacker input. | Right after the `token.count(".")` check, reject anything outside the JWT charset: `if not re.fullmatch(r"[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+", token): raise AuthError("malformed token")`. Also compare bytes: `hmac.compare_digest(expected.encode("ascii"), s_b64.encode("ascii"))`. Add a test to `tests/test_auth_tokens.py` asserting 401 (not 500) for `hdr.payload.é` and for a non-ASCII header segment. |
| **Must-fix 2** (Important, security) | `yukti/backend/app/auth.py:81-110` | (a) **No fail-closed in prod.** With `YUKTI_ENV=prod` (baked in by P0.9) and the secret missing, every Cloud Run instance silently makes its own `/tmp` key. Tokens then fail across instances, and nothing at startup reports the misconfiguration. (b) **Predictable dev key path.** `/tmp/yukti_dev_persona_key_<uid>` is opened with `O_EXCL`. If another local user pre-creates the file, `FileExistsError` is swallowed and the attacker-chosen key is read, so tokens become forgeable on a shared host. Ownership and mode are not checked. (c) The env key has no minimum length. | (a) If `os.getenv("YUKTI_ENV","dev").lower()=="prod"` and `YUKTI_PERSONA_SIGNING_KEY` is unset or shorter than 32 bytes, raise at first use (or log an error at startup) and fail closed with 401 on every protected route. Never fall back to a file in prod. (b) In the dev fallback, `os.open(path, os.O_RDONLY | os.O_NOFOLLOW)` and `os.fstat(fd)`: accept only if `st.st_uid == os.getuid()` and `st.st_mode & 0o077 == 0`, else use a per-process key and warn. (c) Warn (dev) or refuse (prod) when `len(env) < 32`. Add 2 tests: prod + no key → protected route 401 / `AuthError`; a foreign-mode key file is rejected. |
| **Must-fix 3** (Important, text/voice consistency) | `yukti/backend/app/live_session.py:76`, `:116`, `:126`, `:146`, `:557` | The Gemini Live system prompt and tool descriptions still advertise "switch persona" (`action="persona"`, "e.g. switch role to Director HR"). `spoken_map["persona"]` still says "Now viewing and speaking as {val}." The tool call is refused (R-ROLE), but the prompt invites the model to claim a switch, which contradicts BEH-01 and the §4.1 "text and visual agree" rule. | Delete the `persona` bullet at `:76`, and remove "switch persona" from the descriptions at `:116` and `:146` and from the enum text at `:126`. Add one line instead: "The user's access level cannot be changed in conversation; if asked, say so politely (R-ROLE)." Change `:557` to the R-ROLE copy, or drop the key. |
| Minor 1 | `yukti/backend/app/turn_runner.py:370-373` | Dead `set_persona` branch: unreachable since the guard at `:344`, but it would still call `normalize_persona(val)` and set `session_state.persona`. | Replace with `pass  # P0.4: handled by _role_switch_contract` or remove it. |
| Minor 2 | `yukti/frontend/src/app/page.tsx` (P0.4 hunk, `handlePersonaChange` / renew) | The UI sets the persona chip before `startSession` resolves and ignores failure. The 2-hourly renew calls `startSession(personaRef.current)`, which silently downgrades a DEMO_ADMIN session to a plain persona session. The backend stays authoritative, so this is cosmetic or a demo glitch. | P2H.2: set the chip from the `startSession` result; skip the renew for admin, or re-issue via a dedicated refresh. |
| Minor 3 | `yukti/backend/app/auth.py:278` | The first pattern matches "update the profile of Rajesh" or "change the user" and returns R-ROLE for a legitimate request. | Require `my`/`me` or a role word after `profile|user|access`, or move it to P2H.2 with a false-positive test list. |
| Minor 4 | `yukti/backend/app/main.py:512-550` | The WS has no Origin check. SameSite=Strict blocks cross-site cookie sending, so the risk is low. A first-frame token is accepted from any origin. | Optional: reject an upgrade whose `Origin` is not in `allowed_origins()` (or the same host). |
| Minor 5 | `yukti/backend/app/auth.py:172-178` | `iat` (future-dated) and `nbf` are not checked. This is only relevant if the key leaks. | Optional: reject `iat > now + 60`. |
| Info (deviations accepted) | evidence §Deviations | Stdlib HS256 instead of PyJWT (no new dependency); deferred session rate limit and download ownership (SPEC-06 §4.7 → P2H.2/P4.6); admin voice switch unsupported (P2H.2). All three are reasonable and recorded. | Track in the named packets. |
| Info (design) | `main.py:233-256` + Dockerfile `YUKTI_AUTH_MODE=demo` | In demo mode anyone who can reach the service can start a CMD session. This is by design (SPEC-06 §4.4 demo picker) and is acceptable only while Cloud Run stays IAM-protected. IAP mode (P5.6) closes it. | Keep Cloud Run IAM-only until IAP; note it in the P5.6 packet. |
