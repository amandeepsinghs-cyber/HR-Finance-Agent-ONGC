# G4 review — P0.10 voice self-interruption hotfix (BUG-17, BUG-18)

**Reviewer:** independent G4 (fresh context, read-only on code) · **Commits:** `8a95da5`, `2ac6cb5` on `v3/P0-stabilise` · **Date:** 23-Oct

## Verdict: **CHANGES REQUESTED** (3 must-fix, all small)

The browser half-duplex gate is correct and is what will stop the self-interrupt. But three defects can still cause a self-interrupt or leave voice stuck in the sponsor's 5/5 test:
1. The new **voice barge-in detector fires on ordinary syllabic echo** (simulated: 1.5–3.5 s). That is BUG-17 coming back by a different route.
2. The **backend gate gets stuck closed after a Live reconnect**: state is not reset, so every mic frame is dropped until a typed turn.
3. The **backend `_barge_in_open` flag stays set**, so the backend layer is bypassed during the first reply of every mic session.

Tests pass, `tsc` is clean, the LOW-sensitivity enum is valid and the text flow is unaffected. When MF-1…3 are done this can be APPROVED (code), pending the sponsor's live test.

## Should-fix (not blocking)

- **S-1 Replay buffer is 180 ms, not ~0.6 s** (`page.tsx:156`, `:673`). Worklet frames are 480 samples (30 ms), so 6 frames = 180 ms. It **cannot replay echo-only audio**: it holds the last 180 ms, which fall inside the ≥400 ms loud window. The frames carry AEC-attenuated echo under the user's speech, which can't be avoided. However, the "start of the sentence" claim is wrong (~220 ms+ is lost). Size it to the sustain window (`ceil(sustainMs/30)` ≈ 14 frames). Don't go larger, or it will start to include pre-speech echo. Fix the comment and the evidence.
- **S-2 Frontend gate can stick if `isAudioPlaying()` sticks.** Two ways: Chrome `speechSynthesis` sometimes never fires `onend` on long utterances, and a suspended `playCtx` never fires `onended`. Add a fallback in the gate: treat it as not playing when `playCtx.currentTime > nextPlayTime + 1 s` and no synth is running, or when `synthSpeaking` has lasted longer than about `len(text)/12 + 3` s.
- **S-3 Backend speak bookkeeping is single-slot.** A second speak overwrites `_speak_id`, so A's `turn_complete` is reported as B's id and clears `_is_speak_only` early. The mic gate still stays closed (`_generating` plus the playback estimate) and the frontend drops the late transcripts (`closed`), so the impact is cosmetic or logging only. Keep a FIFO of pending speak ids if Live queues turns.
- **S-4 `SpeakTracker.closed` depends on an input transcription arriving before the agent's output.** If Live sends the first `input_transcription` chunk after the first `output_transcription`, the start of the agent bubble is dropped. The `contract` still makes a bubble when there is one. Also, after a forwarded "let me check" + `turn_complete`, the post-tool spoken answer is dropped for no-contract tool turns. Consider re-opening on the first `audio_chunk` of a non-speak turn. Watch this in sponsor step 5.
- **S-5** Voice barge-in may also be **hard** to trigger: normal speech is about 0.45–0.63 on the sqrt(rms)·2 scale against a threshold of ≥0.6–0.85. That is fail-safe, but tune it with the sponsor.

## Checks against the brief

1. **Half-duplex gate.** Browser: correct. `micGateOpen` blocks while playing and for 300 ms after. `interruptNow` sets the tail to 0 after `stopPlayback` fires the end handler, and playback start re-closes it. Typed speak: the browser gate is open before the first audio, but the backend `_is_speak_only` drops the frames (✅). Tool-call turns: the gate is open only while nothing is playing (✅). Backend: correct while idle, generating, speaking and during the playback estimate (48 000 B/s is correct for 24 kHz PCM16). **Gaps: MF-2 (stuck after reconnect) and MF-3 (bypass).** No timeout or fallback exists on the backend (MF-2 adds one).
2. **speak_id.** Interrupt during speak keeps speak-only and drops its transcripts (✅). Server `interrupted` ends the speak and reports its id (✅). Frontend stale ids don't end a newer speak (✅). Backend stale completion: S-3. Stuck on reconnect: MF-2.
3. **Barge-in maths.** The threshold formula is sound, but the leaky accumulation is unsafe for syllabic echo (MF-1). Replay: S-1.
4. **Live config.** google-genai **2.31.0** in `yukti/backend/.venv`. `types.StartSensitivity.START_SENSITIVITY_LOW` exists and serialises to `realtime_input_config.automatic_activity_detection.start_of_speech_sensitivity="START_SENSITIVITY_LOW"`. The converter handles `realtime_input_config` on both paths. ✅
5. **Tests.** Backend `test_voice_gate.py` + `test_h1_hardening` + `test_role_escalation` + `test_degraded_copy` + `test_auth_tokens`: **75 passed**. Full backend suite: **447 passed, 4 failed**.
