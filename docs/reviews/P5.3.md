## Must-fix (blocking)

1. **The coverage-claim regex is too broad and drops grounded sentences** (`app/brain/grounding.py`, `_COVERAGE_CLAIM_RE`).
   `\b(only|up\s+to|upto|until|...)\b.*\b(FY\s?\d{2,4}|20\d\d|data|...)\b` matches ordinary analytic prose. Reproduced:
   ```
   check_numeric_grounding('Net profit grew only 2% in FY2024. Revenue was 5.', {2.0, 5.0})
   -> ('Revenue was 5.', ['Net profit grew only 2% in FY2024.'])
   ```
   - **Impact:** "why"/trend narrations lose correct sentences whenever they use "only", "up to" or "until" near a year. That is common phrasing, e.g. "rose only 3% in FY23" or "up to FY2025 the trend…". No wrong number reaches the user, but answers get thinner or fall back to the template without any notice. The golden suite didn't catch it because no case narrates that phrasing.
   - **Fix:** anchor the pattern on availability semantics, e.g. `(data|figures|statements?|records?)\s+(is|are)?\s*(only\s+)?(available|exist)\s+(up\s*to|until|till|through)` and `(not\s+available|don'?t\s+have|do\s+not\s+have|cannot\s+access)\b.*\b(FY|20\d\d|data)`. Drop bare `only` / `up to` as triggers. Add a regression test with the false positive above, plus one true positive ("Data is only available up to FY2023.").
2. **`D-65` is not committed.** It is in `<ROOT>/HR and Finance_ONGC/docs/DECISIONS.md` but shows `git status` → ` M docs/DECISIONS.md` (last commit there is `f1bb999`, D-64). AC-03 cites it as recorded. Commit it (or add it to the branch) before the gate is called.
