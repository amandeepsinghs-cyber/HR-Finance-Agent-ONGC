## 3. Deviations: assessment

| Deviation (evidence §5) | Assessment |
|---|---|
| Side-tab: last-N tokens instead of a hard cut at column 165 | **Sound.** A cut at 165 would drop AR26 p.24 FY17, which ends at about column 169 (#13). The side-tab words are not numeric, so they never enter the last-N set. |
| Last-N rule vs digits inside labels | **No mis-assignment in the actual data.** I audited every emitted line. Labels that contain digits (`(C2-C3)`, `(000’ Tonnes)`, `(MMM3)`) do not produce numeric tokens. The only label token that counts as numeric is the leading `-` child marker in AR24:874–878. Those lines have 11 numeric tokens, so the last 10 are correct. Only 3 lines have fewer than 10 tokens, and each was verified by position (#26, #27, #41). No lines were skipped. In principle, though, a line with N−1 values plus one numeric label token (`- Foo`, `Note 35`) would be mis-assigned silently, because the position check runs only when `len(vals) < n`. This is follow-up F1 (not blocking: the inputs are fixed and fully audited). |
| Balance-sheet pages ("Statement of Financial Position") not parsed | **Acceptable and in scope.** SPEC-01 §4.2.1 says "read until the Ratio and Analysis block ends". Equity, borrowings and employees for FY13–FY16 are still covered by the AR22 "Performance at a Glance" rows (#30, #32). The dropped pages are AR24 L1061/L1159 and AR22 L303/L420. They should be tracked for P1.3 or a follow-up (F3). |
| "Total Expenses" definition break | **Sound and verified.** `test_total_expenses_definition_break` shows AR26 TE + DD&A = AR24 TE. Only the cross-check key changes (`total expenses excl dda`). The bronze `raw_label` stays verbatim, which is correct for bronze. P1.6 must map this label by vintage (F2). |
| 3 unflagged FY24 failures (Δ 427 ₹ mn) | **Sound.** One reclassification touches 3 lines consistently (other income, total income, provisions). It is pinned in the test and routed to `fact_financial_line_conflict` in P1.6. 0.2% is far below the 5% stop trigger. |

| Extra keys (`report_vintage`, `is_nil`, `source_page_label`, `notes`) and `uv.lock` | Fine. They add to the §5.3 schema without changing it, and the lock file makes builds reproducible. |

## 4. Units, provenance, truth rules

- **Units:** money rows are `INR_mn` (from the `(` in million)` caption). Physical rows are MMT, BCM, kT, and mn_m3 for AR22/24 natural gas in MMM3 (#18–#34 units are correct). Ratios are `ratio`, `(%)` rows are `pct`, EPS/DPS/BVPS/MVPS are `INR_per_share`, Debtors Turnover is `days`, and employees are `count`. No rows are scaled; `value_inr_cr` is left to the loader (§4.2.7).
- **No LLM or fabricated values:** `ten_year.py` uses only regex, tokens and column positions. Every `parsed_value` comes from `parse_token(raw_value_text)`, and that token sits on the cited `source_text_line`. Hard-coded numbers appear only as test expectations and in `KNOWN_UNFLAGGED_FAILURES`. There are no plugs or computed rows (BUILD §4.3 rules 1–2 hold: the tests assert values, not shapes).
- **Page lineage:** `source_page` follows the §4.1 form-feed rule. The folio offset is +2 for AR24/26 (p.23/21, 24/22) and AR22 (18/16 … 21/19), which matches SPEC-01 §4.1.

## 5. Follow-ups (non-blocking, can be done in P1.3/P1.6)

- **F1 (robustness):** in `financial_ssot/extract/ten_year.py:268-269`, run the column-position check for **every** data line, not just those with `len(vals) < n`. Assert that each value token's right edge is within about 6 columns of its header's `right`, or that `assign == list(range(n))`. On failure, record the line as `skipped`. This turns a silent mis-assignment (a numeric label token plus N−1 values) into a visible skip. Add one synthetic test line, e.g. `"- Note 35   1  2 … 9"`.
- **F2 (lineage fidelity):** `raw_value_text` holds the glued ratio (`1.66:1`), not the printed `1.66 : 1` (`ten_year.py:131`). Either store the original span text, or say in the docstring that ratios are whitespace-normalised. For the AR26 `Total Expenses` rows, consider `notes='excl_dda_definition'` so that P1.6 does not depend on the cross-check key.
- **F3 (scope tracking):** add a checklist or backlog item for the AR24/AR22 "Statement of Financial Position" 10-yr pages (evidence §5.3) so the dropped balance-sheet history is not lost.
