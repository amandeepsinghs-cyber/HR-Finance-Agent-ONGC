   - `build_visual` accepts optional `periods: Optional[List[str]] = None` (via `_resolve_stmt_periods`, G4 r2 S6) and constructs `stmt_spec = build_statement_spec(...)` across `pnl_statement`, `balance_sheet`, and `cash_flow_statement` (passing `bs_cash_by_period=load_snapshot_bs_cash_by_period()` into `cash_flow_statement`, G4 r2 M3).
   - When `v3_field_enabled("statement")` is `False` (default), `build_visual` preserves 100% legacy v2 output including all 4 P&L KPIs (`Consolidated PAT (Group)` included, G4 r2 M1).

   - `turn_runner.py:490-500` (G4 r2 S5): when a single-FY statement visual carries `[fy, prior_fy(fy)]` in `stmt_periods` for YoY calculation, defaults `req_fy` to `session_state.spec_history[-1]["period"]["fy"]` so `"Show this as a waterfall"` bridges `fy` directly.
   - **Multi-FY statement query deferral (G4 r2 M4, Lead decision `#59`):** `build_statement_spec` and `presenter.build_visual` support multi-FY statement rows (`periods=["FY26", ..., "FY22"]`), as verified by the 5-year fixtures, while end-to-end multi-FY statement query compilation/pivoting from wide snapshot rows is deferred to **P2F.2** (multi-year statement payload, after **P1.10a**).
