# P0.9 evidence — packaging: data-in-image vs BigQuery-only; Dockerfile fix

**Step:** P0.9 · **Branch:** `v3/P0-stabilise` · **Bug:** BUG-13 (part) · **Packet:** [P0.9](../delegation/packets/v3/P0.9.md) (written and executed at P0 start) · **Status:** pre-G4 · **No image was built or deployed** (sponsor instruction)

## Result
- **Decision: data-in-image + BigQuery primary.** The 7 runtime `financial_build/data` files (≈3 MB) and a new `snapshot_manifest.json` are copied into the image. On Cloud Run a BigQuery/ADC outage now gives the honest P0.3 "Local snapshot 2026-10-22" answer instead of an empty or failed finance answer.
- `snapshot_manifest.json` holds a deterministic `snapshot_date` (2026-10-22), the label, and sha256 hashes of the 7 files. `compiler._local_snapshot_date()` reads it first, because file mtimes change on `git clone` / `docker build` and would otherwise show the build date as the snapshot date.
- `Dockerfile`: new COPY block. Adds `ENV YUKTI_ENV=prod` (docs/openapi off, P0.5) and `YUKTI_AUTH_MODE=demo`, plus documented runtime secrets: `YUKTI_PERSONA_SIGNING_KEY` (required, Secret Manager), optional `YUKTI_DEMO_ADMIN_PASSPHRASE`, `YUKTI_ALLOWED_ORIGINS`, `YUKTI_ENABLE_ADMIN` left unset. No secret is baked in.
- `.dockerignore`: excludes `**/logs/` (P0.4 audit JSONL), `**/.env*` and `financial_build/data/stress_test_*`. The copied files are not ignored.
