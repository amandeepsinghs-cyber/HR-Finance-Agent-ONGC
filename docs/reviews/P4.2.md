## Should-fix (not blocking)

- **S1** `statement_builder.py:542`: rows **without** a `verified` key are treated as verified. That includes every snapshot / `ssot_corporate_*` row, which the compiler itself labels "unverified". This is acceptable before P1 only because provenance stays `local_snapshot` and the flag is off by default. Add a TODO and a test so the check becomes `r.get("verified") is True` when P1 lands.
- **S2** `statement_builder.py:620`: when a prefix is present, the builder replaces the reported label with a curated canonical label. For example, "A5. Investments in Subsidiaries, JVs & Associates (HPCL, OVL, MRPL, OPaL)" becomes "Investments in subsidiaries, joint ventures & associates". BUG-39 asks only for prefixes to be stripped, so prefer `clean_statement_label(raw)`. Separately, stripping "Less:" hides deductions that are stored as positive numbers (CF "Income taxes paid" +9,820 inside OCF). Sign normalisation is an SSOT/P1 concern; flag it there.
- **S3** `frontend/src/contracts/answerContract.ts:10`: `VisualType` lacks the `'sensitivity_grid' | 'tornado'` stubs that the ledger row says go into both schema and TS (the schema has them).
- **S4** `STATEMENT_LINE_META:261-262`: the CF free-cash-flow memo is `kind:"subtotal"`, so it renders ruled after the Closing-cash total; it should be a level-1 `line`. "Total assets" and "Total equity and liabilities" sit inside the current_assets and current_liabilities sections (`:200`, `:225`). Cosmetic.
- **S5** `turn_runner.py:492-500` is outside the packet's file list. It is effectively flag-gated (`stmt_periods` only comes from a `statement` dict) and is needed because single-FY answers now carry 2 periods. Accept, but list it in the evidence doc.
- **S6** The period-derivation block is copy-pasted three times in `presenter.py` (P&L/BS/CF); extract a helper. EPS rows (₹) sit inside a ₹-crore table, and the `EPS_BASIC` label "Basic and diluted EPS" sits next to a separate `EPS_DILUTED` row. Nits.
