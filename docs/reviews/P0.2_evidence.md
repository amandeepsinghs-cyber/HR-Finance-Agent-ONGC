# P0.2 evidence — `resolve_fy("FY 2024-25")` regression

**Step:** P0.2 · **Branch:** `v3/P0-stabilise` · **Bug:** BUG-20 · **Spec:** SPEC-11 · **Status:** pre-G4

## Result
`YYYY-YY` and `FY YYYY-YY` forms resolve to one Indian FY again ("FY 2024-25" → FY25). Both named red tests are green, and 12 new EN/HI/Hinglish cases were added.

## Change (`yukti/backend/app/semantic/normalize.py`, `resolve_fy` only)
1. In the explicit-range branch, a match is **not** a range when the two years are adjacent (`yy == (yyyy+1) % 100`), joined only by a dash, with no `FY` on the right-hand side and no range word (`to/and/through/from/between`). Such a match falls through to the single-FY rules.
2. The single-FY `YYYY-YY` rule also accepts `fy2024-25` (no space). Before, that form fell to the bare-`FY2024` rule and returned FY24.
3. The "N-year" fallback (`"10-year trend"`) no longer fires when preceded by a tenure word (`over`, `more than`, `for`, `at least`, `up to`, `>`). This restores `"officers posted over 5 years in Delhi"` → `None` (the second assertion of `test_fy_dash_forms_and_over_n_years`). `"over the last 5 years"` is still a range.

## Ambiguities resolved (recorded for G4)
- **Packet §6 "over 5 years → last 5 FYs" vs the existing test** (`"officers posted over 5 years in Delhi"` → `None`; editing existing expectations is forbidden). The test wins. "over the last 5 years" is a range; "posted over 5 years" is tenure. SPEC-07's V19 "> 5 years in Delhi" question depends on this reading.
- **`"2023-25"` (non-adjacent):** §6 says "keep the pre-change behaviour; do not invent a new rule". The code path for this form was not touched, so it behaves as at base `9922239` (range FY23–FY25). No test asserts it.
- **`"2024-2025"`:** kept as a single FY25, as at base. The packet's "both sides carry FY/4 digits" range rule is applied only when the right-hand side carries `FY`.
