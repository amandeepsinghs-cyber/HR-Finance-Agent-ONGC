## Verdict: **CHANGES REQUESTED (1 must-fix, small)**

**The NSE data, the weekly closes and the sanity beta are correct and reproducible. One latent bug must be fixed before any Yahoo chart JSON is saved: the Yahoo provider lets monthly bars overwrite daily bars.** All 226 manifest hashes match. 113 equity and 113 index files parse to the same closes as my own parser. I reproduced β_raw = 0.7375 independently. The fetchers are polite and make no attempt to get around rate limits. The bug does not affect any number produced today, because there are no Yahoo files and the chain falls through to `nse_archive`. Once Yahoo files are saved, though, the bug would quietly corrupt daily prices and the P1.9 beta.

## Must-fix

| # | Where | Problem | Change |
|---|---|---|---|
| M1 | [market_provider.py:112-116](../../financial_ssot/extract/market_provider.py) (`YahooFileProvider.get_prices`); [yahoo.py:120-149](../../financial_ssot/extract/yahoo.py) (`parse_chart`) | The `YahooFetcher.endpoints()` file names sort as `..._10y_1d_...` before `..._max_1mo_...`. `_dedupe` keeps the **last** row, so a monthly bar (dated at the month start, close = month-end or latest close) **overwrites the daily bar on that date**. Monthly bars before the 10-year window are also mixed into the "daily" series. The comment says "keeping the first per date", which does not match the code. **Reproduced:** with a daily file at 100.0 and a monthly file at 999.0 for 2025-01-01, `get_prices` returns 999.0 from the `max_1mo` file, plus an extra 2023-11-28 monthly row. | Record the bar interval in each row (from `meta.dataGranularity`, or parsed from the file name). Make `YahooFileProvider` use only `1d` bars, or let daily always win over monthly. Add a test with a daily and a monthly fixture on the same date. |

## Should-fix (not blocking)

1. [market_provider.py:54](../../financial_ssot/extract/market_provider.py) `UA` is a fixed desktop-Chrome string, used for both Yahoo and NSE. It is not rotated, and nothing else is spoofed: no cookies, crumbs, session priming or parallel requests. In the spirit of "no bot-bypass", prefer an honest UA (e.g. `ongc-hrfin-ssot/1.0 (+contact)`), or record in the D-45 note that a static browser UA is used.
2. The tests replace `sleep` with a no-op and never check the NSE ≥ 3 s spacing. Add a test that the sleeps are `[3.0, …]` between NSE requests. The code enforces the spacing ([market_provider.py:355-362](../../financial_ssot/extract/market_provider.py)), and the manifest shows a minimum gap of 3.0 s between the 226 saves, so this only adds a regression guard.
3. [market_provider.py:414-417](../../financial_ssot/extract/market_provider.py) and `:389-392`: if the index file returns a non-200, non-403/429 status (e.g. 404), the code saves `index_file=None` and carries on silently. The week's index close is then missing, and the equity and index series can fall out of alignment. Count and print these cases in the CLI summary. This did not happen in the current pull: 104/104 weeks align.
