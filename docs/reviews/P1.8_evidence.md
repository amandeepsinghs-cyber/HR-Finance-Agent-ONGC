## 3. Page-reference accuracy
- **`source_page`** = number of `\f` before the text + 1 (SPEC-01 §4.1). Every non-`_flow` AR text has one form feed per PDF page. Text page counts match `pdfinfo` for all 8 PDFs (for example FY26 684/684).
- **Independent check against the PDFs** (scratch script `page_spotcheck.py`). For each sampled chunk it measures the share of the chunk's words (≥ 4 letters) found on the claimed PDF page and on the pages either side. Result: 40/40 have overlap ≥ 0.97 on the claimed page and are lower on both neighbours. Samples: FY17 p.168/174/504/136/349, FY18 p.179/116/310/184/14, FY19 p.293/65/287/572/163, FY22 p.309/334/288/252/338, FY23 p.72/482/40/188/543, FY24 p.458/187/369/77/365, FY25 p.242/580/425/279/395, FY26 p.361/65/577/51/306.
- **Printed-folio anchors** (unit test `test_known_page_labels` plus the FY26 test): FY24 PDF p.247 → "245", FY26 PDF p.23 → "21", FY26 PDF p.98 → "96". These match SPEC-01 §4.1 and §10.3.
- The folio offset varies by AR: +2 for FY17, FY19, FY22–FY26 and +4 for FY18 (taken from the printed folio on each page, not assumed).

## 4. Retrieval hit@5 (`financial_ssot/knowledge/eval_ar_retrieval.py`)
The packet has no question set, so I built one with 22 questions. The ground truth is **computed from the AR text**: the gold pages are the PDF pages where all of the question's regexes match. A question counts as a hit when one of the top-5 chunks has the same FY and a gold page. Retrieval uses the FY pre-filter (fy, fy−1).

| Run | hit@5 |
|---|---|
| Vector + section re-rank | 17/22 = 0.77 |
| **Hybrid: 32 vector candidates, then section + lexical re-rank (shipped default)** | **18/22 = 0.82** |

Misses in the shipped run:
- Q10 (FY26 dry-well decommissioning policy): the top-5 holds the same policy sentence from AR FY25 p.441/283 and FY26 p.307. The answer is right in substance but misses the strict FY26-only gold.
- Q12 (FY25 MD&A, windfall tax abolished, p.222): only one sentence in a 300-token MD&A chunk mentions it; notes chunks rank higher.
- Q18 (FY24 windfall/SAED): the FY23 MD&A p.173 ranks first, so the answer comes from the wrong FY.
- Q19 (FY19 windfall, p.158).

Fixed by the lexical re-rank: Q14 (Mumbai High) and Q17 (Daman Upside). Full per-question output: `financial_ssot/out/ar_retrieval_eval.json`.

## 6. Deviations and open questions
- **D1: ≥ 15,000 chunks cannot be met under the packet's own size rules.** The corpus is about 2.23 M whitespace words, or about 2.9 M estimated tokens. Chunks of at least 300 tokens with a 60-token overlap advance at most 240 tokens each, so the ceiling is about 12k chunks before the short/numeric drops. Pages under 300 tokens produce one chunk each. The chunker already uses the finest split allowed (every page with ≥ 462 words is cut into windows of about 300–360 tokens), which gives 8,712. Reaching 15k would need windows of about 200 tokens. **Recommendation:** accept 8,712 and change the criterion to "≥ 8,000", or allow 200–600-token windows.
- **D2: query embedding is client-side.** The retriever uses `text-embedding-005` with `RETRIEVAL_QUERY` through the Vertex API, and passes the vector as an `ARRAY<FLOAT64>` parameter. SPEC-01 §8.2 names `ML.GENERATE_EMBEDDING`, which needs a BigQuery remote model and connection plus IAM. None of these exist, and creating them is out of scope.
- **D3: hybrid lexical re-rank added.** The re-rank adds a 0.05 × term-overlap bonus over 4 × top_k vector candidates. It took hit@5 from 0.77 to 0.82. Setting `LEXICAL_WEIGHT=0` gives pure vector ranking.
- **D4: files beyond Part B's three.** For Part A I added `financial_ssot/knowledge/{__init__.py, embed_load_ar.py, eval_ar_retrieval.py}`, `yukti/backend/app/knowledge/{__init__.py, ar_retriever.py}` and `yukti/backend/tests/test_ar_retriever.py`. `sections.yaml` is written as JSON-compatible YAML because the `financial_ssot` project does not depend on PyYAML, so `uv run` works without a lockfile change.
- **D5: known tagging weaknesses** (cosmetic; `heading` keeps the raw title):
  - AR FY22 PDF p.18–57 is tagged `ten_year`. FY22 has no running titles, so "Standalone Performance at a Glance" carries forward until the Board's Report heading.
  - The statement pages just before the notes are sometimes tagged `notes`.
  - BRSR is a separate document from FY24 on, so brsr has 0–5 chunks in FY24–FY26.
  - `line_codes` holds keyword tags only (`KW.*`), because `financial_ssot/dim_financial_line.csv` does not exist yet. The chunker picks it up automatically when it exists.
- **Not wired into the app yet.** No caller in `yukti/` uses `ar_retriever.py`; P2F.5 (SPEC-08 §6) does that.
