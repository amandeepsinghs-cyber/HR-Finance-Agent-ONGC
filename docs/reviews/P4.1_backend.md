## Must-fix (blocking)

### M1 — The single-metric waterfall shortcut takes over new data questions
`yukti/backend/app/turn_runner.py:361-369`

The new block turns any "total revenue … waterfall" utterance into `set_chart_kind` **whatever is on screen**. It then reaches `elif rows and cols:` (`:466`), which builds an untyped waterfall from the previous answer's rows and says it succeeded. I reproduced this: with a 4-asset revenue bar chart on screen,
- `"Ankleshwar का टोटल रेवेन्यू का वॉटरफॉल चार्ट बना दो"` → spoken `"मैंने वर्तमान डेटा को स्क्रीन पर वॉटरफॉल चार्ट के रूप में प्रदर्शित कर दिया है।"`, `ui_action=set_chart_kind`, chart = the 4-asset rows as a waterfall (not Ankleshwar, unsigned);
- `"Show the Ankleshwar total revenue as a waterfall chart"` → same, in English.

Before this commit these queries went to the data pipeline. **Fix:** apply the shortcut only when `last_vis` is a single value (`type=="kpi"` or ≤1 row). Otherwise let the turn go to the pipeline, or return `single_value_error()` copy directly. Add a regression test with a multi-row non-KPI visual on screen.

### M2 — Waterfall re-plot of a multi-year P&L / multi-period statement still draws an unsigned waterfall (BUG-08, BEH-04.12)
`yukti/backend/app/turn_runner.py:466-476` (fall-through `elif rows and cols:` → `build_chart_spec(kind="waterfall", rows=last_rows)`), plus `bridge.py:246-249`.

- Reproduced: with the multi-year P&L trend on screen (wide rows `fiscal_year, revenue_from_ops_cr, ebitda_cr, pbt_cr, …`, no `line_code`), `"Show this as a waterfall"` gives `ui_action=set_chart_kind` and `"I've replotted the current data as a waterfall bridge chart on screen."`, with the raw year rows as an untyped waterfall. That is the "₹11 L cr" BUG-08 shape again, which SPEC-09 §4.3 rules out: "never rebuild from `last_rows`" for statements.
- BEH-04.12 requires "Which year?" chips (FY26/FY25/…) for a multi-period statement. Instead, `_extract_rows_and_period` silently picks `periods[0]` when a multi-period statement dict is passed with `period=None` (`turn_runner.py:435` calls `bridge(stmt_source)` with no period).

**Fix:**
- (a) Treat `pnl_statement` multi-FY visuals (and any statement dict with >1 period and no selected period) as statements: return "Which year?" chips, or a BridgeError-style note with no `ui_action`. Never call `build_chart_spec(kind="waterfall")` on them.
- (b) Pass the selected period explicitly into `bridge()`.
- Add a test for each.

### M3 — The presenter's BridgeError path produces an empty `kind:"table"` chart under `type:"chart"`, with no honest copy
`yukti/backend/app/brain/presenter.py:195-203`

If statement lines don't reconcile and a waterfall was requested on the first turn (e.g. "Show FY25 P&L as a waterfall"), `wf_rows=[]` → `build_chart_spec(...)` returns `{kind:"table", data:[]}`, and `:203` still sets `vis["type"]="chart"`. Reproduced with PBT +₹2,000 cr: `type=chart kind=table n=0`. The `bar` request gives the same result. No BridgeError reason reaches the narration, so the narrator can describe a chart that doesn't exist.

**Fix:** on `BridgeError`:
- keep `vis["type"]="table"` (the statement table);
- leave `vis["chart"]` unset;
- attach `b_res.message(lang)`/reason (e.g. `vis["note"]` or a caveat the narrator must read) so the turn text is the SPEC-09 §4.3 step 6 copy.

Add a test using `error_subtotal_mismatch`-style rows through `build_visual(chart_kind="waterfall")`.
