# P4.6 G4 review: export backend (commit c55cafc)

**Reviewer:** reviewer-p46 (independent, fresh context) · **Date:** 2026-10-24 · **Branch:** `v3/P4-visual` · **Parent compared:** 0e84527 (c651a99 + frontend-only stub)

## Verdict: **CHANGES REQUESTED**

The format writers work: the PDF with Noto and Devanagari is correct, the xlsx statement layout is right, and so are the CSV BOM, docx, eml, the honest Sheets/Docs toasts and the naming regex. Cross-principal 403 and expiry 404 work on the main paths. The pipeline does **not** meet the core SPEC-10 §3/§4.10 rule that "exports never re-query data; they serialise the session's stored contract". The route still trusts client-supplied `rows`, `contract` and `content`. There are also four security defects:

- a fail-open download path
- xlsx formula injection
- CSV formula injection
- a 1 h sweep that contradicts the advertised 24 h `expires_at`

Every probe below was reproduced by the reviewer with `TestClient` (script: reviewer scratch `probe_p46.py`).

## Must-fix (blocking)

### M1. Client-supplied data is exported as the source (SPEC-10 §3, §4.10.1), [main.py:519-568](../../yukti/backend/app/main.py#L519-L568)
- If `turn_id` is missing **or unknown**, the route builds the export from `req.contract`, or from `req.rows` + `req.columns`. Probe 1d: a junior sends `turn_id:"does-not-exist"` plus arbitrary rows, and the server returns 200 with the client rows exported.
- `enforce_export_rbac` does collapse rows that use policy-recognised names. Probe 1 passes: E2_HR posting 9 named rows gets `grade/headcount`, with `<5` on E5 and the `_aggregate` suffix. But anything outside the policy column list passes through verbatim:
  - Probe 1b: `full_name`, `staff_no` and `posting` are exported unmasked, `masked=false`.
  - Probe 1c: a client `visual.statement` with "Person 1 salary 123456" is exported. `enforce_contract` never inspects statements.
- `req.content` (free markdown) is rendered into PDF/docx bodies for every persona: [main.py:620](../../yukti/backend/app/main.py#L620) and [main.py:633](../../yukti/backend/app/main.py#L633).
- Impact: Yukti-branded, audit-logged files ("Source: … Masked: No") can carry arbitrary, unverified content. The audit row claims the turn was exported. This breaks the integrity guarantee that RBAC review depends on.
- **Fix:**
  - Require `turn_id` for `xlsx|csv|pdf|docx|eml|sheets|docs`.
  - Unknown turn → 404. Never fall back to `req.contract`, `req.rows` or `req.content`.
  - Keep `columns` only as an intersection filter (this already works).
  - If a legacy rows path must stay for one release, gate it to `CMD`/`DIR_*`, mark `masked`/banner "client-supplied", and log `delivery`/`data_classes=["client_supplied"]`.
  - Delete the `contract` field from `ExportRequest` ([main.py:197](../../yukti/backend/app/main.py#L197)).

### M2. The download fails open when the artifact record is missing, [main.py:755-791](../../yukti/backend/app/main.py#L755-L791) + [export_audit.py:610-612](../../yukti/backend/app/export_audit.py#L610-L612)
- `verify_artifact_access` returns `None` both for "expired" and for "no record". The route then still globs `exp_<id>.*` and serves the file with **no owner check**.
- Probe 3b: CMD creates an export, the in-memory record and sidecar are removed, and E2_HR downloads it with 200.
- This happens in real use: the sidecar write failure is only logged ([export_audit.py:575](../../yukti/backend/app/export_audit.py#L575)), and other instances or restarts may lack the in-memory record.
- **Fix:** `rec is None` → 404 (and remove any orphan file). Only serve when a record exists and the owner matches. Make the sidecar write failure fail the export (500) instead of a warning.

### M3. xlsx formula injection, [export_tool.py:577-579](../../yukti/backend/app/tools/export_tool.py#L577-L579) (also title A1 :451, headers :565, statement labels :498, Definition sheet)
- openpyxl turns any string starting with `=` into a formula. Probe 4: `=HYPERLINK("http://evil","x")` is stored with `data_type='f'`. (Strings starting with `+ - @` stay as `s`, which is safe in xlsx.)
- **Fix:** add `_safe_cell_text(v)`: if `str` and `v[:1] in "=+-@\t\r"`, prefix `'` (or set `cell.data_type='s'` after assignment). Apply it to every data, label, header and title cell. The DCF formula sheets (`_build_dcf_sheets`) are exempt because they are server-authored.

### M4. CSV formula injection, [export_tool.py:693-698](../../yukti/backend/app/tools/export_tool.py#L693-L698) and the statement branch [:650-662](../../yukti/backend/app/tools/export_tool.py#L650-L662)
- Probe 4: `=HYPERLINK(...)`, `+cmd|' /C calc'!A0`, `-2+3` and `@SUM(A1)` are all written raw.
- **Fix:** prefix `'` to string cells starting with `= + - @ \t \r` (OWASP CSV injection). Numeric values stay raw, so negatives as numbers are unaffected. Add tests for both writers.

### M5. The 1 h sweep contradicts the 24 h expiry in the contract, [main.py:467-481](../../yukti/backend/app/main.py#L467-L481) vs [export_audit.py:41](../../yukti/backend/app/export_audit.py#L41)
- `_sweep_old_exports` deletes files older than `YUKTI_EXPORT_TTL_SECONDS` (default **3600**). Meanwhile the artifact advertises `expires_at = created + 24h` and the route registers with `DEFAULT_EXPORT_TTL_SECONDS`.
- After 1 h the P4.7 frontend gets 404 for an artifact it believes is valid.
- Sidecars (`.exp_*.meta.json`) are never swept, because the sweep skips dotfiles (:478), so they accumulate forever on Cloud Run's RAM disk.
- **Fix:** use one TTL constant (24 h, env-overridable) in both places. Sweep by `expires_epoch` from the sidecar, and delete the sidecar together with its file.

### M6. Turn ownership on voice and live turns is persona-only and truncated, [export_audit.py:501-512](../../yukti/backend/app/export_audit.py#L501-L512)
- `register_turn_contract` is called only from `/api/turn` ([main.py:393](../../yukti/backend/app/main.py#L393)). It is not called from `/api/voice-turn` ([main.py:452](../../yukti/backend/app/main.py#L452)) or the `/ws/live` turns (`live_session.py:398, 531, 1075, 1176`).
- Those turns resolve through the `SessionManager` fallback, which:
  - checks **persona only, not emp_id**, so two users with the same persona can export each other's turns, violating §4.10.1 `(session, turn_id, principal.emp_id)`;
  - reads `session_memory` turns, whose tables are **truncated to 50 rows** (`session_memory.py:70-73`). The voice-driven V19 export of a 60+ row roster would silently lose rows, and the audit `rows` would be wrong.
- **Fix:** call `register_turn_contract(..., emp_id=principal.emp_id)` on every turn path (voice-turn, and live session where the contract is emitted). In the fallback, require an emp_id match, or drop the fallback and return 404.

## Frontend contract (P4.7)
- **Unchanged.** The response is still `{artifact:{export_id,kind,filename,url,rows,columns,masked,created_at,expires_at,sha256}, toast?}` plus the flattened copy. The only addition is `zip` as a CSV kind for multi-table answers, and the naming regex was extended to allow it.
- This is consistent with the lead's 19/19 Playwright run.

## Can a real turn path still be unregistered? Only in edge cases, and those fail closed (403), not open.
- **Covered:** `/api/turn`, `/api/voice-turn`, and every `live_session` site that calls `execute_turn_async`. These are all of the server turn producers.
- **Re-plotted cards** that keep the same `turn_id` export the server's stored contract for that turn, so the data is right. The chart type and options the user chose on the client are not reflected server-side. That only matters for PDF/docx without a `chart_png`, and the frontend sends `chart_png`.
- **Fixture/mock cards** (design-system, offline) get 403. That is acceptable, as the coordinator noted.
- **Situations that give 403 even though the turn is real:**
  1. `_TURN_STORE` is a global, per-process LRU capped at 500 turns ([export_audit.py:627](../../yukti/backend/app/export_audit.py#L627)). Once a turn is evicted, the session fallback always refuses, because session turns never carry `emp_id` (see F1).
  2. When Cloud Run has more than one instance, both the turn store and the artifact sidecars live in local RAM. An export or download that lands on a different instance gets 403/404. Deploy with `max-instances=1` (or session affinity) until the SPEC-03 GCS/Firestore store lands.
