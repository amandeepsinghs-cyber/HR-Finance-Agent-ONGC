2. **Schema:** columns + data types from `<dataset>.INFORMATION_SCHEMA.COLUMNS` (one query per dataset, not per table), in ordinal order.
3. **Profiling (one aggregate query per table, not per column):**
   - `row_count` = `COUNT(*)`.
   - For every `STRING` column: `APPROX_COUNT_DISTINCT(col)` and null count. If distinct ≤ **60**, run a second query for that table that returns, for each such column, the distinct values and their counts (e.g. `SELECT 'col' AS c, CAST(col AS STRING) v, COUNT(*) n ... GROUP BY v` unioned per column) and store `values` (sorted by count desc) and `value_counts`.
   - For `INT64`/`FLOAT64`/`NUMERIC`/`BIGNUMERIC`: `MIN`, `MAX`, null count.
   - For `DATE`/`TIMESTAMP`/`DATETIME`: `MIN`, `MAX` as ISO strings.
   - `BOOL`: count of TRUE / FALSE / NULL.
   - Any column named `fiscal_year` (any type) always stores its full sorted distinct value list as `values`, even if > 60.
   - `ARRAY`/`STRUCT`/`JSON` columns: type only, no profiling.
4. **Output** `app/semantic/semantic_catalog.json` (UTF-8, `indent=1`, keys sorted, deterministic order so a re-run with unchanged data produces an identical file except `generated_at`):
   ```json
   {"version": 1, "generated_at": "<ISO UTC>", "project": "ongc-hr-finance-agent",
    "tables": {"hrfin_gold.ssot_workforce_employee": {
        "row_count": 42171, "kind": "BASE TABLE|VIEW",
        "columns": {"employment_status": {"type": "STRING", "distinct": 2, "nulls": 0,
                     "values": ["Active", "Separated"], "value_counts": {"Active": 22798, "Separated": 19373}},
                    "age_years": {"type": "FLOAT64", "min": 21.0, "max": 60.0, "nulls": 0}}}}}
   ```
5. Byte guard: set `maximum_bytes_billed` = 2 GB per job; print bytes processed per table and a total at the end.
6. CLI: `python scripts/build_semantic_catalog.py [--only hrfin_gold.ssot_workforce_employee ...] [--out PATH]`; default output path is the file in §3.2. Exit non-zero if any table fails, listing the failures.
