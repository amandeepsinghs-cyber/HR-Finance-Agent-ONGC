Cases (`normalize_categorical_filters(sql, CAT)`; assert the substring after rewriting):
1. `SELECT 1 {E} WHERE employment_status = 'active'` → contains `employment_status = 'Active'`
2. `... WHERE cadre='Executive'` → contains `cadre = 'executive'`
3. `... WHERE LOWER(cadre) = 'Executive'` → contains `LOWER(cadre) = 'executive'`
4. `... WHERE employment_status IN ('active','SEPARATED')` → contains `employment_status IN ('Active', 'Separated')`
5. `... WHERE employment_status NOT IN ('active')` → contains `employment_status NOT IN ('Active')`
6. `SELECT 1 FROM hrfin_gold.ssot_workforce_employee e JOIN hrfin_silver.employee_master m ON e.emp_id = m.emp_id WHERE e.employment_status = 'Active'` → contains `LOWER(e.employment_status) = 'active'` (tables disagree on spelling)
7. `... WHERE employment_status = 'retired'` → unchanged (unknown value)
8. `... WHERE emp_name = 'abc'` → unchanged (not a profiled categorical)
9. `SELECT 1 FROM hrfin_gold.mart_postings WHERE employment_status = 'active'` → unchanged (table not in catalog)
10. `... e WHERE e.cadre = 'EXECUTIVE'` (with `{E} e`) → contains `e.cadre = 'executive'`
11. `` SELECT 1 FROM `ongc-hr-finance-agent.hrfin_gold.ssot_workforce_employee` WHERE employment_status = 'active' `` → contains `'Active'`
12. Idempotence: for cases 1–6, `n(n(sql)) == n(sql)`
