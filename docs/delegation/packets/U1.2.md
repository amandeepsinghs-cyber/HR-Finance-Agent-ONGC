## 5. Exact requirements
1. In `format.ts` add and export:
   - `fmtPct(value: number, decimals = 1): string`, which returns e.g. `"21.5%"` (uses `fmtNum`; handles NaN/Infinity → `"—"`)
   - `sharePct(part: number, total: number, decimals = 1): string` = `fmtPct((part / Math.max(1e-9, total)) * 100, decimals)`, preserving the current semantics where the code uses `Math.max(1, total)` (keep `Math.max(1, …)` if that's what the call site does: **output must be identical**)
   - `fmtInt(n: number): string`, an Indian-grouped integer (use `groupIndian`)
2. Replace ad-hoc formatting in `options.ts` and `plan.ts`:
   - display strings built with `.toFixed(n)` + `%` → `fmtPct` / `sharePct`
   - `Math.round(n).toLocaleString('en-IN')` → `fmtInt(Math.round(n))`
   - **Keep** numeric (non-display) `Number((…).toFixed(1))` computations as they are (e.g. `share_pct: Number(...)`, smoothing at options.ts:744). Only display strings change.
3. `utils/numberFormat.ts`: if it has **no** importers, replace its body with re-exports that delegate to `charts/format.ts` (`formatIndianNumber` → a thin wrapper over `fmtValue`/`fmtNum`; `formatPercent` → `fmtPct`), plus a `/** @deprecated use '@/charts/format' */` doc comment. If it **has** importers, keep the signatures and make them delegate. Output for typical inputs must match the old function (check 3 examples and list them in your report).
4. Tailwind `fontSize` scale (keep the existing `kpi-*` keys unchanged), adding:
   ```js
   'display': ['2.25rem', { lineHeight: '1.15', letterSpacing: '-0.02em', fontWeight: '600' }],
   ```
